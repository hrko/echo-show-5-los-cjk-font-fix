## 現在の機能と維持したい性質

CJK と欧文の install / restore ZIP を別々に生成しています。CJK は Noto Sans CJK / Serif CJK の可変 TTC、欧文は公式公開版 Google Sans Flex です。欧文は `sans-serif` と `sans-serif-condensed` のみを置き換え、元の Roboto / RobotoCondensed 20ファイルを補助フォールバック用に残します。serif / monospace の独立置換は将来用の担当範囲だけ予約しており、今回追加する必要はありません。

重要なのは、各パッチが自分の担当部分だけを変更・復元し、他のパッチの状態を維持することです。XML 全体の古いスナップショットを戻す方式にはしないでください。共通構造・対象スロット・フォントのハッシュ照合、未知の変更の拒否、コメント・改行を含む担当外バイト列の保持、再適用、書き込み順序と属性設定など、現在の安全性・独立性を維持したいです。担当外スロットの内容の正当性まで検証する契約ではありません。

既存のホスト実装 `scripts/font_slots.py` は標準ライブラリの `hashlib` / `re` だけを使っています。Python 化によってこの種の処理の二重実装を減らしたいです。ビルド用の fontTools や ext4 解析などを、端末側にもすべて持ち込むことを求めているわけではありません。

TWRP の ARM32 環境で実行できるランタイムが必要です。Python バイナリだけでなく標準ライブラリ・共有ライブラリ・起動時の依存関係も検討対象になります。一般の Android アプリ向け Python 配布物が、そのまま TWRP で動くことは未確認です。出典・バージョン・ハッシュ・ライセンスと再現可能な取得方法を明確にしたいです。System に Python を恒久インストールする必要はありません。

前セッションでは「まず TWRP の一時領域で同梱 Python が動くことを確かめ、XML 処理を共有する。mount や SELinux 設定は必要に応じて Edify に残せる」という方向性を話しました。これは候補であり、実装の分担を固定する指示ではありません。

## Python 化を検討した理由と現在の修正

ホストでは動いた recovery 処理が、実機では以下の環境差に当たりました。

1. Toybox に awk がなく、BusyBox もありません。ただし独立した `/sbin/awk` はあり、バージョンは `20121220` でした。
2. TWRP の `/sbin/sh` では `hash` が `alias -t` のエイリアスになっており、同名のハッシュ計算関数が呼ばれず停止しました。
3. 単独 awk は `if (!active)` という式で `illegal arithmetic operator 345` を出しました。最小の再現例で確認済みです。`active == ""` ならその例は動きました。

`recovery/compose-fonts.sh` には単独 awk 対応と関数名の `file_hash` への変更を入れています。`recovery/split-fonts.awk` の単項否定を比較式に変更する編集も作業ツリーにあります。ただし **最後の awk 編集は再ビルド・実機検証を完了していません**。途中で Python 化の議論へ移りました。これらは Python 化前の暫定修正であり、残す必要があるかは設計に応じて判断してください。

単独 awk 対応時点の全26ホストテスト、後から追加した `hash` エイリアスの回帰テスト、最後にビルドした4 ZIP の統合テスト2件は成功しています。最新作業ツリー全体のテストを最後に一括実行した、という意味ではありません。
